**AWS adapters** (13 of 13 complete, #336): Each brick gets a single `aws.py` adapter with a `service` parameter selector. Backend classes live in a `backends/` subfolder to stay under 200 LOC. All AWS adapters expose `infrastructure_spec()` returning structured resource requirements.

**CDK generation** (#336 Phase 3): The blueprint base converts `infrastructure_spec()` dicts into deployable CDK L2 Python projects. The pipeline is: normalizer (3 spec shapes → `NormalizedResource`) → resolver (VPC detection, IAM generation → `InfraBlueprint`) → CDK renderer (per-brick stacks, network stack, app.py). Supports 15 AWS services. See `bases/blueprint/runtime/` for implementation.

**CI/CD pipeline generation** (#336 Phase 3): The blueprint base generates GitHub Actions workflows with OIDC auth. Default stages: test → synth → deploy-staging → deploy-prod. No hardcoded AWS credentials — uses `aws-actions/configure-aws-credentials@v4` with role assumption.

**For local dev without Docker**: Use memory/mock adapters. Most recipes can run this way.
